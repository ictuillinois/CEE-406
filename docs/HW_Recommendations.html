01

What a frontier model does to the current problem set

I ran the existing ten homeworks against the question every instructor is now asking: could a student produce a passing submission without understanding anything? The honest answer for most of them is yes, and the reason is structural rather than a failure of design. Eight of the ten homeworks are built primarily on end-of-chapter problems from Huang. Those problems are published, their solutions circulate, and their setups are short enough to paste into a chat window in full. A model does not need to have memorized Problem 12-7 to solve it; it needs only to be handed the two sentences that state it.

HWCurrent basisExposureWhy
HW1 Seven definitional questions (Q1–Q7) Total Q2, Q3 and Q4 are Huang's own end-of-chapter questions almost verbatim — 1.4, 1.5/1.6, and 1.10/1.11 respectively. The rest are answered well by a general-purpose model in one prompt, with no data and no judgment involved.
HW2 Problem 7.2, an Mr fit, a lime essay, a CBR reduction High The lime synthesis is a pure essay prompt. The Mr dataset is published in this repository as hw2-part1-data.xlsx — it can be uploaded and regressed in a single turn.
HW3 Problems 2-1, 2-2, 2-3, 2-5 High Textbook problems with circulating solutions. The chart-reading skill the assignment intends to build is invisible in the submitted answer.
HW4 Problems 2-6, 2-7 + a defined 4-layer run Mixed The layered run needs software, which helps. "Interpret at least four observations" is an essay prompt attached to numbers the model can regenerate.
HW5 Problems 6.2, 6.3, 6.6, 6.7, 6.9 High Arithmetic on tabulated factors. Exactly the shape of task current models are most reliable at.
HW6 Problems 8.6, 8.8, 8.10 High Same. DRIP is offered as a check, not required as evidence.

HW10 Bespoke ACR/PCR + FAARFIELD + LCA Low Also strong: a specific aircraft against specific runway codes, and an LCA whose answer depends on assumptions the student has to state.

The course already contains its own answer. The two homeworks that resist a language model — HW8 and HW10 — are precisely the two that were written from scratch around a specific scenario and required real software. Nothing below is a new philosophy. It is the generalization of what is already the best work in this problem set, extended over the other eight, with the repository's tools doing the job WinJULEA and FAARFIELD do in HW8 and HW10.

One clarification is worth making early, because it changes what "AI-immune" should mean. The goal is not a homework a student cannot get help with. That target is both unreachable and undesirable — a student who uses a model to understand why the deflection basin's outer sensors see only the subgrade has learned something, and we should want that. The goal is a homework whose deliverable cannot be produced without the understanding. Help is fine. Substitution is not. Every device below is chosen to widen the gap between the two.

02

Ten devices that make the difference

These are the mechanisms the redesigned homeworks are assembled from. Most homeworks use three or four. They are listed here so the assignments below can refer to them by name rather than re-explaining the logic ten times.

D1 — Per-student data

The dataset is generated from the student's UIN

A model cannot solve a problem whose numbers it has never seen and cannot obtain. This single change neutralizes the solution-manual problem entirely, and it costs one deterministic generator script.

D2 — Prediction first

Write the answer you expect before you run the tool

The graded artifact is the gap between prediction and result, and the diagnosis of that gap. A model can produce either half; it cannot produce a student's specific wrong intuition and the correction of it.

D3 — Designed disagreement

Two legitimate methods, two different answers

Huang is full of these and says so out loud. The deliverable is the reconciliation and the choice, not the numbers. This is the device with the highest teaching value per unit of grading effort.

D4 — Inverse framing

Not "compute X" but "find the input that makes X happen"

Searching a parameter space requires iterating a solver. A model that cannot run the tool cannot do the search, and a model that hallucinates the answer is caught by the tool immediately.

D5 — Process evidence

Seeds, iteration counts, screenshots, exported tables

Tool state is cheap for a student who did the work and impossible to fabricate convincingly. The Monte Carlo seed in the reliability tool exists for exactly this reason.

D6 — Break the model

Find where the theory stops being true

"Find an input set where Boussinesq and the layered solution differ by more than 50%, and state the rule you inferred." Requires understanding the assumption, not the formula.

D7 — Consequence chaining

This week's output is next week's input

A design decision in HW5 becomes traffic in HW7 and damage in HW8. Errors propagate and must be caught. It also mirrors how real design actually fails.

D8 — The red-team part

Get an AI to answer, then prove it wrong with the tool

Credit for catching the error. This converts AI from contraband into an object of study, and teaches verification as a reflex. Details in §08.

D9 — Micro-defense

Three minutes of screen recording on one figure

Cheap to produce, fast to grade, and close to unfakeable. Reserve it for the one figure in each homework that carries the reasoning.

D10 — Significant-figure honesty

State how many digits your answer deserves

Almost every model output is falsely precise. Asking for a defended precision, given the input variability, forces engagement with what the number actually means.

On D2, the one to adopt first if only one is adopted. Prediction-first costs nothing to implement — it is a sentence added to each part — and it changes the epistemics of the whole assignment. A student who writes "I expect the tensile strain to fall as the asphalt gets thicker" and then finds a maximum at 3 inches has had the experience the course exists to deliver. That experience is not transferable, not searchable, and not promptable.

03

The ten homeworks, redesigned

The sequence keeps the existing ten slots, the existing due dates, and the existing phase structure, so this is adoptable without renegotiating the syllabus. Two changes to coverage are proposed: Chapter 10 (Reliability), which currently has no homework at all, becomes a substantial part of HW7; and Chapter 13 (Overlays), currently listed against HW10 but not actually assessed, becomes the spine of a new capstone HW10. Airfield ACR/PCR moves to HW5, where it belongs — it is a loading-compatibility problem.

HW 01

Forensic diagnosis of a pavement you can walk to

Replaces seven definitional questions with a field investigation. The student reads a real section, infers what is underneath it from what has failed on top, and commits to a diagnosis they will be held to for the rest of the semester.

Ch. 1 · 9.1 Distress Identification Manual LayerGlyph reference D1 D2 D7 D9

Parts

  • P1Each student is assigned a 100 ft section of pavement in Champaign–Urbana by UIN. Photograph and log every distress present, classifying type, severity, and extent against the LTPP manual. Minimum five distinct distresses; a section with fewer is itself a finding. (Students who cannot reach the assigned section — remote, mobility, or a January section under snow — survey any pavement they can reach and submit its location with the photographs; the assignment needs a real section, not a specific one.)
  • P2Classify the section as flexible, rigid, or composite, from the surface evidence alone. State what you observed that decided it and what observation would have overturned it.
  • P3Separate your distresses into load-associated and environment-associated. For each, name the mechanism from Ch. 1 and Ch. 9 and say which layer it implicates.
  • P4Draw the cross-section you believe is under your 100 ft, with thicknesses. This is a defended guess, not a lookup — justify each layer from the distresses and from what the road carries.
  • P5Prediction, sealed: sketch the deflection basin you expect this section to produce under a 9,000 lb FWD drop, and name the sensor that would confirm your diagnosis. This is submitted with HW1 and timestamped — it is only evidence because it exists before you know the answer. You will be handed it back in HW10.
Why this resists substitution. The photographs are unique, geotagged, and dated. The inference chain runs from evidence the model cannot see to a conclusion it cannot check. And P5 plants a prediction that gets scored eight weeks later against the student's own backcalculation — the single strongest continuity device in the redesign.
HW 02

The fit that lies: material characterization as an act of judgment

Keeps the resilient-modulus and CBR work, but moves the grade from "did you get k₁, k₂, k₃" to "should anyone trust the model you just fitted, and what does it cost in asphalt if they shouldn't?"

Ch. 7 · App. D mr-fitter cbr aashto D1 D3 D8 D10

Parts

  • P1Per-student triaxial dataset (30 points, realistic scatter, two injected outliers). Fit the generalized k₁–k₂–k₃ model in the Mr Fitter. Report the parameters, R², and the parity plot.
  • P2Identify the outliers from the residual structure, not from R². Refit without them. Decide whether their removal is defensible and say what physical event could have produced them. A student who removes points because it raises R² has failed this part even with a better R².
  • P3Model competition. Refit the same data with the simpler two-parameter k₁θk₂ form. R² will favor the three-parameter model — it always does. Report both R² values and the stress state at which the two models diverge most, in psi and in percent. Then argue which you would hand a designer, on grounds other than fit — and say whether the divergence you just measured is large enough to matter at the stresses your pavement will actually see.
  • P4Use both models to predict Mr at a bulk stress double the largest you tested. Report the two numbers and the percentage between them. The two fitted the same data and now disagree; explain what that gap is made of, and whether either is admissible evidence.
  • P5Per-student CBR penetration data with a concave-up toe. Reduce it in the CBR tool with and without the origin correction. Convert both to Mr, run both through the AASHTO Design Studio, and report the difference in inches of asphalt that the origin correction is worth.
  • P6Select a PG binder for your assigned climate (App. D). State the pavement temperatures you designed for and what you would change for a 20-year-later climate.
The pedagogical center is P5. A tangent construction in a lab standard becomes a quantity of asphalt. Students routinely treat data reduction as bookkeeping; this makes the consequence structural and visible, and it requires three tools in sequence with the student's own numbers moving between them.
HW 03

Where the stress actually goes

One hand solution survives, because a student who has never read a Boussinesq chart does not know what the solver is doing. Everything else becomes a search through the parameter space for results that contradict intuition.

Ch. 2 · 3.4 · App. B stress-explorer lea D2 D4 D6

Parts

  • P1By hand, from the printed charts: stresses, strain and deflection under a per-student two-circle load (Huang Ex. 2.1 pattern). Then the same case in the Stress Explorer. Reconcile the two, and attribute the residual difference to chart-reading error versus anything else.
  • P2The critical thickness hunt. For your assigned modulus set, sweep the asphalt thickness in the LEA tool and find the thickness at which tensile strain at the bottom of the asphalt is maximum. Predict first (D2). Then explain, mechanically, why a thinner asphalt layer can crack less than a thicker one — and why that stops being true above the critical thickness.
  • P3Single wheel versus dual wheels at equal total load and contact pressure. Find the asphalt thickness at which the dual-wheel case stops being more critical for εt. State which tire configuration you would specify on a thin pavement and why the answer flips on a thick one.
  • P4Break the model (D6). Holding your assigned geometry fixed, sweep the modulus ratio E₁/E₂ and report the two values at which the one-layer Boussinesq solution crosses 5% and 50% disagreement with the layered solution. Huang states the rule qualitatively in §2.1; your job is the number. Then say whether your own assigned structure sits inside or outside it, and by how much.
P2 is drawn from Huang §3.4.1, where the critical thickness is reported as a finding rather than derived. A student must locate it numerically for their parameters. A model asked the same question will usually assert that thicker asphalt always reduces tensile strain — which is wrong, and which the tool disproves in thirty seconds. That makes P2 a natural red-team part (D8).
HW 04

Which response governs, and does your ranking survive?

The four-layer analysis stays. What changes is that the critical locations are no longer given — the student has to find them — and that any sensitivity ranking must be tested for whether it generalizes.

Ch. 2 · 3 · App. C lea stress-explorer WinJULEA D2 D4 D5 D9

Parts

  • P1Per-student four-layer structure. Depth profiles of σz, εz, σr, εr and deflection, produced in both the LEA tool and WinJULEA. Where they disagree, diagnose it — interface bonding, unit handling, or integration tolerance — and say which you trust.
  • P2Locate the critical points yourself. Do not assume the maximum tensile strain is under a tire. Search the (r, z) plane for a dual-wheel load and report where it actually occurs, with a contour supporting the claim.
  • P3Sensitivity tournament. Rank E₁, E₂, E₃, h₁, h₂ by their influence on εt and separately on εc, using ±30% one-at-a-time perturbations. The two rankings differ; explain the mechanics.
  • P4Then break your own ranking. Repeat P3 at a very different base thickness. Huang §3.4 warns that conclusions from a sensitivity study are valid only for the parameter set they were run at. Did your ranking survive? Report honestly.
  • P5Design inversion (D4). For a target εt, map the (h₁, E₁) combinations that achieve it. Choose one point on that iso-strain curve and defend it on cost, constructability and rutting grounds — not on strain, since every point on the curve is equal in strain.
P4 is the part that separates a student who ran a procedure from one who understands what a sensitivity study is worth. It is also, in my view, the single most transferable idea in the whole course — and it cannot be answered without two full sets of runs.
HW 05

Traffic: the number every other number rests on

Keeps one hand calculation for the W-4 scaling logic, then turns the rest into an investigation of how much the design traffic can be trusted — and adds the airfield compatibility problem, which is a loading question and was orphaned in HW10.

Ch. 6 · 6.2 esal-calculator lea acr D1 D3 D7 D10

Parts

  • P1Per-student W-4 loadometer table. Compute the truck factor with the ESAL Calculator, and by hand for one load group, showing the scale-up from weighed axles to counted axles explicitly.
  • P2Test the fourth-power rule. Using the tool, check whether EALF ∝ (L/18)4 holds across the load range and across axle types. Report where it holds, where it breaks, and what changing pt does to the exponent.
  • P3Designed disagreement (D3). Compute the ESWL of your assigned dual wheel by all four of Huang's criteria in the ESWL Comparator — Boyd and Foster, equal vertical stress, equal deflection, equal tensile strain (§6.2). Report your own four numbers and the spread between them — the book's example spans 32%; yours will not be the same. Then sweep the pavement thickness and report the thickness at which your spread is widest. Which criterion would you use for a thin pavement, a thick pavement, and an airfield? Defend each by naming the failure mode it is actually watching, and say what your own widest-spread thickness implies about where the choice matters most.
  • P4Which is worse for design traffic: a 20% error in truck count, or a 20% error in truck weight? Answer with the tool, then explain the answer with the exponent. Then state how many significant figures your design ESAL deserves (D10).
  • P5ACR/PCR compatibility for an assigned aircraft against three assigned runway codes. For any runway where operation is refused, state exactly which of the five code fields refused it and what the airport would have to do about it.
The ESWL part is the best untapped material in Chapter 6. Three criteria, three answers, all legitimate, and Huang explicitly warns that transposing between methods produces erroneous results. There is no correct number to retrieve — only a defended selection. P4's design ESAL is carried forward into HW7 and HW8 (D7).
HW 06

Drainage, and the structural credit nobody connects to it

The drainage design stays. What is added is the link students almost never make: the drainage coefficient m is a structural quantity, and a decision about permeability is a decision about thickness.

Ch. 8 · 11.3 drainage aashto DRIP D1 D3 D7

Parts

  • P1Per-student site: climate, subgrade, geometry, gradations. Full inflow estimate and drainage-layer design in the Drainage Designer, cross-checked against DRIP. Report both; where they differ, say why.
  • P2Three inflows, one design (D3). Estimate design inflow by Ridgeway, by Cedergren, and from groundwater. They disagree, sometimes by a factor of several. Choose a design inflow and defend it — including what you are protecting against by choosing the larger one.
  • P3Design the layer to reach AASHTO "good" drainage (2 hours to 50%) and separately "fair" (1 day). Report the permeability–thickness combinations each requires.
  • P4The structural consequence. Take the m₂ that each drainage quality earns, feed both into the AASHTO Design Studio at your HW5 traffic, and report the difference in required thickness. Then answer: is the faster drainage layer worth building?
  • P5Check filter criteria on your assigned gradations. Where they fail, propose a fix — graded filter or geotextile — and name the specific failure mode you are preventing.
P4 makes drainage structural rather than a separate topic that happens to live in Chapter 8. It also requires the student's own HW5 traffic, so the numbers are not transferable between students.
HW 07

AASHTO 1993, its reliability, and its limits

The largest single change in the proposal. Chapter 10 currently has no homework anywhere in the course; here it becomes half of HW7, because reliability is not an advanced topic — it is the reason the design equation has a zRs₀ term at all.

Ch. 11 · Ch. 10 aashto esal-calculator reliability — new D3 D4 D5 D10

Parts

  • P1Solve for the required SN at your own HW5 design traffic. Then produce three different layer combinations that all satisfy that SN and the minimum-thickness rules, and choose one on cost and constructability grounds. The SN split is not unique and students should learn that from doing it, not from being told.
  • P2Sweep reliability from 50% to 99.9%. Plot SN against R and report the inches of asphalt per decade of reliability. Where is the knee, and what does its position depend on? Then locate your assigned functional class in Huang Table 11.16 and say whether the recommended band sits before or after that knee — and what that implies about the band.
  • P3Reliability from the inside (Reliability tool). Give every input its coefficient of variation from Huang Tables 10.9–10.11. Compute the design's actual reliability by variance propagation. Then rank the inputs by their share of the total variance and answer the question that ranking exists to answer: would you spend the next $50,000 on more asphalt, tighter construction control, or a better traffic count?
  • P4Run the same design through Taylor's expansion, Rosenblueth's point estimates, and Monte Carlo. Report all three with your seed (D5). Where they disagree, say which you would defend and why the disagreement exists.
  • P5The extrapolation audit. Huang §11.3 states the conditions the AASHTO equations were calibrated under: 1,114,000 axle load applications at one site near Ottawa, Illinois, between October 1958 and November 1960; a temperate climate averaging 34 in of precipitation; 28 in of frost penetration; and poorly drained A-6 and A-7-6 subgrades at CBR 2 to 4. Your design is twenty years and several million ESAL, on your own assigned subgrade and climate. Name the three extrapolations you are making. Quantify the most dangerous one against your own design — re-run your HW7 P3 reliability with that input moved to the edge of the Road Test's range and report how many points of reliability you lose. Then say what one measurement would close it, and roughly what that measurement costs.
P3 is the question a practicing engineer actually faces and it has no retrievable answer — it depends entirely on which of the student's own inputs dominates their own variance. It is also the clearest possible demonstration that reliability is not a safety factor bolted on at the end but a statement about which of your inputs you know least well.
HW 08

Mechanistic-empirical design, and how much of it to believe

The existing homework is already the strongest in the course and its structure is kept intact. Three parts are added, all aimed at the same target: the predicted life is a number with an uncertainty, and students should leave knowing roughly how large it is.

Ch. 3 · 11 · App. F damage lea WinJULEA reliability D2 D3 D7 D10

Parts

  • P1Unchanged: IDOT-style flexible mechanistic design for the assigned county and traffic.
  • P2Sublayering convergence. How many asphalt sublayers are needed before εt stops moving? Find the point of diminishing return and report the cost of over-refining as well as under-refining.
  • P3Transfer functions in the Damage tool from your own strains. Then: which distress governs — and does the answer change between summer moduli and spring-thaw moduli? Run both seasons.
  • P4Calibration humility. The transfer-function coefficients are national defaults. Perturb the fatigue exponents and the rutting coefficients across their published range and report the resulting spread in predicted life. Then state how many significant figures your predicted life deserves (D10).
  • P5Compare your mechanistic thickness against the AASHTO thickness you produced in HW7 for the same traffic and subgrade. They will not match. Reconcile them, and say which you would submit for construction.
P4 usually produces order-of-magnitude spreads in predicted life. Students find this genuinely unsettling, which is the point: it is the difference between believing a design method and understanding one. P5 closes the D7 chain that started with HW5's traffic.
HW 09

Rigid pavements: three ways to be wrong about a slab

Five textbook problems become one slab that has to survive the day, the night, two design methods that disagree about what will kill it, and two published formulas that disagree about how hard the wheel is even pressing.

Ch. 4 · 5 · 12 westergaard pca aashto D1 D2 D3 D9

Parts

  • P1Calibrate, then compute. Load the tool's Huang Ex. 4.2–4.4 preset and confirm it returns the printed ℓ = 42.97 in and σinterior = 143.7 psi before you trust it with anything (§07). Then your own per-student slab: interior, edge and corner stresses and deflections, with one case worked by hand to show the radius of relative stiffness is understood.
  • P2Which edge answer do you build to? (D3) The tool reports edge stress for both a circular and a semicircular contact — 330.0 against 279.4 psi on the book's slab, an 18% spread. Explain the mechanical reason the semicircle is larger, decide which you would carry into a thickness design, and say what it would cost you to be wrong in each direction. Do the same for the two corner formulations, which differ by 2% in stress but 11% in deflection — and answer why a formulation can agree on one and not the other.
  • P3Find the critical hour. Superpose curling and load stresses for a daytime positive gradient and a night-time negative gradient. Which combination of load position and time of day governs? Predict before computing (D2) — most students predict wrongly, and the reason they predict wrongly is worth a paragraph.
  • P4PCA against AASHTO (D3). Design the slab both ways. In the PCA method, report whether fatigue or erosion governs for your axle spectrum — it is not the same answer for everyone in the room, so compare with two classmates and account for the difference from your three spectra. Then answer: what is erosion accounting for that the AASHTO equation structurally cannot see?
  • P5Choose a joint spacing and defend it against three distinct failure modes — curling stress, joint opening and steel demand, and faulting. The Joints tool computes all three, and will show you that friction stress never governs (Huang gets 19.5 psi against a tensile strength near 200), so the real fight is between curling, which wants short slabs, and everything a joint costs. Say which you let win. Then note that the dowel bearing stress feeding your faulting number depends on which of Huang's three load-reach conventions you adopted, and defend that choice too.
  • P6Huang §5.3.1 and §5.3.3 print KENSLABS and ILLI-SLAB results beside the Westergaard closed form for the same slabs. Read those comparisons and name two things the closed form structurally cannot represent. Say whether either would change your design, and by roughly how much. (No finite-element tool is needed — and none exists in the toolbox yet; see §09.)
P3 is the best counterintuitive result in the rigid half of the course: at night the slab curls upward and the corner becomes critical, which is the opposite of the daytime case most students carry in their heads. It is also a strong candidate for the three-minute micro-defense (D9). P2 exists because the toolbox previously hid it — see the audit in §09.
HW 10

Rehabilitation: reading a pavement that already exists

The capstone. Chapter 13 currently appears on the syllabus but is never assessed; here it becomes the whole assignment, and the life-cycle assessment stops being an accounting exercise because it is run on rehabilitation strategies the student designed themselves.

Ch. 9.4 · 13 · App. E backcalc — new aashto lca reliability D1 D2 D3 D5 D7 D9

Parts

  • P1Per-student FWD survey: ten stations along one project, each with a full basin. Backcalculate layer moduli at every station in the Backcalculation Studio. Report the seed you started from as well as the moduli you ended at (D5).
  • P2Delineate uniform sections. From the station-to-station variability, divide the project into design sections and justify the boundaries. Report the coefficient of variation of your backcalculated subgrade modulus within each section you propose, and across the project as a whole. Then argue uniform-section against point-by-point design (§13.5.1) using those two numbers — if sectioning did not reduce the variability, it bought you nothing.
  • P3The central disagreement (D3). Estimate SNeff three ways — condition survey with Table 13.7 coefficients, NDT via Eqs. 13.22–13.26, and remaining life from fatigue damage. They will not agree. Huang's instruction is explicit: "The designers should use all three methods whenever possible and select the best estimate through their own judgment. There is no substitute for experience and judgment." That sentence is the assignment.
  • P4Design the overlay for each of your three SNeff values. Report all three thicknesses, choose one, and state what you would tell a review board that challenged the choice.
  • P5Which moduli did the data actually determine? Load the tool's Thin surface preset first — a basin generated from a known 200/18/8 ksi structure with 1.5% instrument noise. Fit it. The subgrade returns within 1%, the basin matches to about 1.5% RMS, and the surface modulus comes back near half its true value. Now do the same for your own sections: identify any layer the basin cannot see, report those moduli as ranges rather than values, and say what one additional measurement would most reduce your uncertainty.
  • P6Run the LCA on your strategies: mill-and-overlay at your thickness, full reconstruction, and do-nothing-until-failure. Report GHG per lane-mile over 20 years and identify the dominant stage. Then answer whether the lowest-carbon option is the one you chose in P4, and if not, what would have to change for it to be.
  • P7Close the loop. Retrieve your HW1 P5 sealed prediction of a deflection basin. Compare it against what you now know. Score yourself.
This is the assignment the whole redesign is built toward. It is unfakeable — ten unique basins, an iterative inversion, three disagreeing estimates and a defended choice — and it is also the closest thing in the course to what a pavement engineer actually does on a Tuesday. P7 makes the semester a closed loop rather than ten disconnected weeks.
If the semester can absorb twelve homeworks instead of ten

HW7 is doing a lot of work above. In a twelve-slot semester I would split it: AASHTO design and layer selection stay in HW7, and reliability, variability and the extrapolation audit become a standalone HW8 built entirely on the Reliability tool and Ch. 10. I would also split HW10, putting backcalculation and section delineation in one week and overlay design plus LCA in the next — P1 through P7 as written is genuinely two weeks of work. The ten-slot version above is the compressed form, and the compression falls on those two.

04

Red-teaming the proposal against itself

A document that claims a homework is AI-resistant should be made to prove it. This section attacks the redesign in §03 the way a capable student with a capable model would, states what survives and what does not, and revises the claim to match. Three findings are uncomfortable, so they come first.

The threat model

"Can AI do it?" is not one question. It is three, and the redesign performs very differently against each.

LevelWhat the student doesCost to them
T1 Paste Types the question into a chat. No data, no files, no tools. Seconds.
T2 Upload Uploads their own CSV bundle and asks a model with a code interpreter to solve it. A minute.
T3 Reimplement Uploads the data and has the model rebuild the tool's equations from the citations, then runs the whole analysis. An afternoon, once — then reusable all semester.

Three uncomfortable findings

1. The tools are not a moat. Every tool cites the equations it implements — "Huang Eqs. 4.41–4.45" — because §07 argues a student should be able to verify them. That same citation is a complete specification for a model. The compiled JavaScript also ships to any browser that opens the page. "You need the tool" stops nobody at T3, and the honest response is not to hide the equations; it is to stop counting them as a barrier.

2. Per-student data defeats sharing, not computation. Device D1 makes the solution manual worthless and makes copying a classmate detectable in seconds. It does nothing against a student who uploads their own file. That is still a large win — it removes the cheapest path entirely — but a narrower one than "AI-resistant" implies.

3. About a fifth of the parts, as first drafted, were bookwork in disguise. Every sub-part phrased "explain why", "name the mechanism", or "state the rule" is answerable from Huang alone, at T1, in a single prompt. Those are precisely the parts a model does best. Eight have been rewritten in §03 to require a quantity only that student holds; the audit below lists what remains.

The red-team log

I attempted representative parts as the attacker at each level. What follows is what actually happened, including where the attack succeeded.

Part attemptedLevelResult
HW2 P1 — fit k₁, k₂, k₃ to the triaxial set T2 Solved The regression is four lines of code. Upload the CSV, ask for a log-space least-squares fit, get the parameters and R².
HW2 P2 — find the two injected outliers T2 Solved Residual analysis finds them reliably. The judgment about whether removal is defensible was generic prose — hence the rewrite.

What survives T3

Four things, and it is worth noticing how few of them involve a computer.

Anchor 1

Physical evidence

HW1's photographs of an assigned section, geotagged and dated. A model cannot manufacture them and a classmate's are of a different street. The most robust part of the redesign.

Anchor 2

Time-ordered artifacts

A prediction is evidence only if it was recorded before the answer existed. That is submission mechanics, not wording: the sealed sketch must be collected and timestamped with HW1 and handed back in HW10. Otherwise it is one more paragraph to generate.

Anchor 3

Live defense

Three minutes of screen recording on one figure (device D9). Cheap to produce, fast to mark, and the only part of a take-home that tests whether the person who submitted it can still explain it. One per homework is enough.

Anchor 4

The exam

Unassisted and invigilated — and the reason the homework can afford to relax about numbers at all. Nothing in this proposal works without it, and §08's weighting assumes it stays.

Honest ratings against T3, the strongest attacker. "Exposed" does not mean a part is bad; it means it is not carrying the integrity load and should not be weighted as though it were.

The revised claim. This redesign does not make homework impossible to do with a language model, and no take-home artifact can. What it does is narrower, and worth stating exactly:

It eliminates the free paths — the published solution, the classmate's file, the answer that exists before the question is asked. It raises the cost of the remaining path from seconds to an afternoon of genuine set-up, and makes that path demand enough understanding to steer that a student who walks it has learned something on the way. And it concentrates the ungameable evidence into four cheap places — a photograph, a timestamped prediction, three minutes of talking, and an exam — so the grade rests on those rather than on trusting the rest.

A student determined to avoid learning can still pass the homework. They will not pass the exam, and they will find the three minutes very long.

One of them written out in full

Everything in §03 is a specification, not an assignment. The gap between the two is where this kind of redesign usually dies — "defend your choice" is easy to write and hard to grade. So here is a single part, HW3 P2, exactly as it would reach a student, followed by the rubric a TA would mark it with. If this part is gradeable in ten minutes, the other forty are too.

HW3 · PART 2 · THE CRITICAL THICKNESS · 20 POINTS

Open assignments.csv from your dataset bundle and read your four-layer structure. Throughout this part, hold the base, subbase, and subgrade exactly as issued and vary only the asphalt thickness h₁.

(a) Predict, before you compute anything. In two or three sentences, say what you expect the tensile strain at the bottom of the asphalt layer to do as h₁ increases from 1 in to 12 in. Draw the shape you expect by hand. Write this down first and do not revise it later — part (d) is graded against it, and a prediction you got wrong is worth exactly as much as one you got right.

(b) Compute. Using the Layered Elastic Analysis tool, evaluate εt at the bottom of the asphalt for h₁ = 1, 2, 3, 4, 5, 6, 8, 10, 12 in. Tabulate, and plot εt against h₁. Refine your spacing near any turning point until you can state the critical thickness to ±0.25 in.

(c) Report the critical thickness for your structure, and the strain there. State your modulus ratio E₁/E₂ alongside it.

(d) Explain the mechanism — not the curve, the mechanics. Why does adding asphalt increase tensile strain below the critical thickness? Your answer must identify what is carrying the load in each régime and what changes between them. Then state plainly where your part (a) prediction was wrong and what assumption produced the error.

(e) The design question. A colleague proposes a 2.5 in overlay on a section currently at 2 in of asphalt. Using your curve, tell them what happens to fatigue life, and whether you would build it. If your answer is "it depends", say on what.

(f) Red team. Ask any AI system: "In a three-layer flexible pavement, does increasing the asphalt thickness always reduce the tensile strain at the bottom of the asphalt layer?" Paste the response verbatim. Then say whether it is correct for your structure, and cite the specific rows of your own table that settle it. Full credit whether the system was right or wrong; the credit is for the verification.

Deliverables. The table, the plot, the hand-drawn prediction from (a) (photograph is fine), and at most one page of prose covering (c) through (f). Every number gets a one-line statement of how you checked it.

07

Teaching the instruments, not just assigning them

The redesign leans hard on the toolbox, which creates a failure mode worth naming before it happens: a tool that produces an answer a student cannot sanity-check is worse than no tool at all. It replaces "I don't know how to do this" — a productive state — with "the computer said 4.7" — a terminal one. The same is true of a language model, which is why this section and the next are really one argument.

Tool literacy is not picked up by osmosis. It has to be taught as explicitly as the mechanics are, and it has three parts.

1. The calibration ritual

An engineer never trusts an instrument they have not calibrated. Students do this instinctively in a materials lab and almost never with software. So make it the first move with every tool, every time:

Before you use a tool on your own data, reproduce a number you already know with it. Every tool in the toolbox cites the equations it implements, and several now ship the book's own worked examples as one-click presets — Westergaard loads Examples 4.1, 4.2–4.4 and 4.5; the backcalculation studio loads Example 13.11; the reliability explorer opens on Examples 10.11–10.13. Run the preset. Confirm you get Huang's printed answer. Then load your data.

Graded as one line per homework: "Calibrated the PCA erosion route against Huang Example 12.1 — got 86.4% erosion damage for the 36-kip tandem against the book's 86.5%." Cheap to write, cheap to mark, and it catches unit errors, misread inputs, and the occasional genuine tool bug before they contaminate an entire assignment.

There is a second-order benefit. The FWD Backcalculation Studio's Example 13.11 preset does not quite reproduce the book: the tool's built-in temperature factor is an interpolation, Huang reads 0.92 off Figure 13.18, and SNeff comes out 3.14 instead of 2.88 — a 9% difference on a design quantity. The calibration ritual surfaces that immediately, and the student learns the most important lesson available about engineering software: the number it hands you is only as good as the chart somebody approximated to build it.

2. Three questions for any tool output

Attached to every numeric answer, in every homework, until they become reflex. They are the same three questions that make an AI response safe to use, which is not a coincidence.

Question 1

What does this tool assume that my problem violates?

Layered-elastic analysis assumes static loading, full continuity, and linear elasticity. Your asphalt is viscoelastic, your base is stress-dependent, and your truck is moving. Naming the violated assumption is not pedantry — it tells you the direction of the error.

Question 2

What would this number be if my worst input were 30% off?

One re-run answers it. If the answer barely moves, stop worrying and move on. If it moves a lot, you have just found what the assignment is actually about, and where to spend your remaining time.

Question 3

Can I get within a factor of two by other means?

A hand calculation, a limiting case, a chart, a dimensional argument, or a second tool. Not to duplicate the answer — to catch the order-of-magnitude error that no amount of internal consistency will reveal.

3. A progression, not a toolbox dumped on week one

Twelve tools handed over at once is an inventory, not a curriculum. The homework sequence in §03 already implies a progression in what students are asked to do with a tool; it is worth making that progression explicit, because it is the spine of the redesign.

StageHomeworksWhat the student doesThe competency
Read HW1–HW2 The tool computes something whose answer is knowable another way. Fit the data, reduce the curve, check against a hand result. Trusting an instrument you have calibrated — and noticing when the calibration fails.
Drive HW3–HW6 The student poses the question, not the assignment. Sweep a parameter, hunt a maximum, search an iso-strain curve, size a layer to a target. Turning a design question into a computable one — the step most students never practice.
Doubt HW7–HW9 Quantify how much the answer is worth. Propagate variance, perturb the calibration coefficients, check whether a sensitivity ranking survives a different parameter set. Attaching an uncertainty to a number, and knowing which input owns it.
Choose HW10 Two legitimate tools disagree. Pick one, defend it to a reviewer, and report what the data could not determine. Engineering judgment under genuine ambiguity — the thing the whole course is for.

The stages are cumulative and the last one is the point. A student who reaches HW10 having only ever operated tools will produce three SNeff values and ask which is correct. A student who has been driven through drive and doubt will produce three values, say which they trust and why, name what would change their mind, and flag the moduli the basin never determined. Those two submissions contain the same numbers. Only one of them is engineering.

08

Being AI-friendly on purpose

Everything above is about making the deliverable inseparable from the understanding. That is the defensive half. The other half matters more, and it is the reason to do this now rather than in three years: students in this course will spend their careers working alongside these systems, and almost nobody is teaching them how to do it responsibly. A pavement course is an unusually good place to learn, because pavement engineering has cheap ground truth — a solver that will tell you within seconds whether the confident paragraph you were just handed is true.

The stance, stated to students in week one

You may use any AI system, for anything, at any point in this course. You must disclose it, and you are fully responsible for every number you submit. An error you did not catch is your error. In this course we will treat these systems the way we treat any other instrument: powerful, fast, occasionally wrong in ways that look exactly like being right, and therefore requiring calibration against something you trust.

What these systems are genuinely good at here — and should be used for

  • Explaining a step you are stuck on. "Why does the radius of relative stiffness have a fourth root in it?" is a question a model answers well, and asking it is strictly better than not asking anyone.
  • Being a demanding critic of your own reasoning. Paste your justification for a design choice and ask it to argue the opposite. This is the highest-value use in the whole course and almost nobody does it.
  • Writing the code around the engineering. Post-processing tool exports, plotting, unit conversion, building the per-station table. The engineering judgment is yours; the scripting does not have to be.
  • Generating test cases. "Give me an input set where these two methods should agree, so I can check my tool is set up correctly."
  • Translating vocabulary. Between AASHTO, mechanistic-empirical, and ICAO terminology, which describe overlapping ideas in incompatible words.

Where they fail, specifically, in this subject

Worth demonstrating live in lecture rather than asserting. Every one of these is checkable in the toolbox in under a minute, which is exactly the point.

  • Iterative numerical work. Backcalculating a modulus set from a basin, or solving Eq. 13.25 for Ep, requires iteration. Models produce a plausible-looking answer in one pass and it is usually wrong.
  • Chart reading. Any value that comes off a Bradbury, Peattie or PCA chart is being guessed at.
  • Counterintuitive results. Ask whether a thicker asphalt layer always reduces tensile strain at its bottom. The common answer is yes. It is wrong, and HW3 P2 makes the student prove it.
  • Committing to a judgment. Asked which of three SNeff estimates to use, models list considerations rather than choosing. Engineering requires choosing.
  • Knowing what varies. They will give you a design life to four significant figures without noting that the input coefficients carry ±40%.

The highest use: building the instrument

Everything in the list above treats an AI system as something you consult. The most valuable thing a student can do with one is different in kind: use it to build a tool that did not exist, and then be responsible for whether the tool is right.

This is not hypothetical for this course. Every tool in the toolbox is a few hundred lines of arithmetic wrapped around equations printed in Huang. A student who can state the equations can now, with assistance, produce a working instrument in an afternoon — and the moment they do, they discover that the hard part was never the code. It was deciding what the tool should assume, what units it takes, what it should refuse to answer, and how anyone would know it is correct.

OPTIONAL · BUILD A TOOL · REPLACES ONE HOMEWORK

Choose one of the tools §09 lists as still missing — the dynamic modulus master curve, the joint load-transfer calculator, the ESWL comparator, the PSI and roughness tool — or propose your own. Build it, using whatever assistance you like.

What is graded is not the code. It is: the equations you implemented and where in Huang they come from; the assumptions you had to make that the book left open; at least three test cases checked against printed worked answers, with the results; one case your tool refuses or flags rather than answering wrongly; and a paragraph on what your tool should not be trusted for. Submit the test output, not a claim that it passes.

A tool that is honest about a narrow scope beats an ambitious one that silently produces nonsense outside it. Say so in the brief.

Three things make this worth a homework slot. It is the most verifiable deliverable in the course — the tool reproduces Huang's printed answers or it does not, and no amount of confident prose substitutes. It teaches the thing the profession most needs and least teaches: that generating code is now cheap and validating it is the entire job. And a good submission enters the toolbox with the student's name on it, for the next cohort — which is a considerably better motivation than a grade.

What this does to collaboration

Worth saying out loud, because per-student data changes the social dynamics of the course and it changes them for the better. When every student holds different numbers, copying stops being possible and helping each other starts being the only thing left. The single transferable asset becomes method: how you found the critical thickness, how you delineated the sections, why you rejected the outlier. That is precisely the thing we want discussed loudly in a study group at 11pm.

So the collaboration policy should be permissive and explicit: discuss method freely, submit your own numbers, name your collaborators. The generator makes the second part self-enforcing — a submission carrying another student's data is detectable by re-running the generator, which takes seconds and requires no suspicion to trigger. That is a far healthier arrangement than one where the rule is "don't work together" and the enforcement is vibes.

Three mechanisms to put this into practice

Mechanism 1

The AI use log

A required one-page appendix on every homework: what you asked, what it gave you, what you kept, and what you found to be wrong. Graded pass/fail on honesty and specificity, worth about 5%. "I did not use AI" is an acceptable entry. Vague entries are not.

Mechanism 2

The red-team part

One part of each homework, explicitly marked: get an AI to answer a specific question, then verify or refute it with the tool. Full credit requires either a confirmed answer with independent evidence, or a caught error with the evidence that caught it. Students quickly discover that finding errors is easier than confirming correctness, which is itself the lesson.

Mechanism 3

The verification habit

Every numeric answer in every homework carries a one-line statement of how it was checked — a second method, a limiting case, a dimensional argument, or a sanity range. This is not an AI policy. It is engineering practice, and it happens to make unverified model output obvious.

A worked example of a red-team part, as it would appear on HW3

P2c (red team, 8 points). Ask an AI system: "In a three-layer flexible pavement, does increasing the asphalt thickness always reduce the tensile strain at the bottom of the asphalt layer? Answer yes or no and explain." Record the response verbatim. Then use the LEA tool with your assigned moduli to determine whether the response is correct. If it is wrong, produce the thickness sweep that proves it and identify the specific reasoning error. If it is right, produce the sweep that confirms it and explain why the model got a counterintuitive case correct. Full credit either way — the credit is for the verification, not for the model being wrong.

The exam remains the checkpoint where numbers are produced without assistance. Nothing here reduces that — it is what allows the homework to relax about numbers and grade thinking instead.

Tools: seven built, two repaired, one proposed

Three things the redesign depends on did not exist, and are now built and tested — the two tools against Huang's printed worked answers, the generator against itself. Each ships the book's own examples as presets, so a student can check the instrument before trusting it, which is the habit §07 asks them to build.

Building them exposed a second problem. Writing §07 meant asserting that every tool can reproduce a printed answer — so I checked, and five of the fourteen tools had their physics embedded in the React component with no tests at all. That included the Westergaard tool, which the whole of HW9 rests on. Auditing those is described below; it turned out to matter more than the next new tool would have.

Built · /tools/backcalc/

FWD Backcalculation Studio

A measured deflection basin goes in; layer moduli come out. Two independent routes: full layered-elastic inversion by Levenberg–Marquardt on ln E, driven by the same App. B solver the LEA tool uses, and the AASHTO 1993 closed form (Eqs. 13.22–13.26). They disagree, which is the assignment. It also reports per-layer sensitivity — how much extra basin error a 20% modulus error causes — so a student can see which moduli the data determined and which are their own seed guess coming back at them. Validated against Huang Example 13.11, which it reproduces exactly (SNeff = 2.88) once the student enters the temperature factor from Figure 13.18 rather than accepting the tool's suggestion.

Built · scripts/generate-datasets.mjs

Per-student dataset generator

The linchpin, and the reason it was the top of the roadmap: device D1 depends on it entirely. One deterministic bundle per student from hash(UIN + salt), in nine handouts covering all ten homeworks — triaxial Mr data with two injected outliers, a CBR curve with a concave-up toe, a W-4 table, a drainage site with gradations, an IDOT scenario, a rigid slab with its axle spectrum, a ten-station FWD survey with a real section break, and every scalar assignment. Plus an instructor answer key. The salt is the security model: this repository is readable by the class, so an unsalted run produces data whose answers any student can re-derive from the source. The CLI refuses to run without one.

Built · /tools/mastercurve/

Dynamic Modulus & Master Curve

The largest untouched body of theory in the book, now reachable. Predicts |E*| by the Asphalt Institute regression (Eq. 7.27) and by Shell/Bonnaure (Eqs. 7.24–7.25) — which disagree by 62% on Huang's own Example 7.10 — then shifts the isotherms onto one master curve and fits the MEPDG sigmoid. Its real finding: superposition holds, but only if the shift slope is fitted rather than inherited. Huang's 0.113 average costs about 25% in modulus on this mix, which prefers 0.064. Validated against Examples 2.16 and 7.7–7.10.

Built · /tools/joints/

Joints & Load Transfer

The half of rigid design that is not slab thickness: dowel group action and bearing stress, tie bars, joint opening, and faulting. It makes HW9's joint-spacing defense quantitative — and carries a third designed disagreement. Huang uses three different conventions for the dowel load reach in three different places: Friberg's 1.8ℓ in the worked examples, Heinrichs' 1.0ℓ in the note saying the examples are wrong, and 1.0ℓ with 0.45W in the faulting model. Which one you adopt can decide whether the design passes. Validated against Examples 4.8, 4.9, 4.11, 4.12 and 4.13 — including Example 4.12's verdict that the book's own dowel design fails by about 10%.

Built · /tools/eswl/

ESWL Comparator

Four published criteria for converting duals to one wheel, computed together. On Huang's own Example 6.1 they give 5630, 6750, 7340 and 7410 lb — a 32% spread — and he remarks that the two which nearly agree do so "by coincidence". Two of the four are integrated from the Boussinesq kernel rather than read off a chart. It also shows that stress and deflection peak at different points under the duals, which is the mechanical reason the criteria differ at all. Validated against Examples 6.1, 6.2, 6.3 and 6.5.

Built · /tools/psi/

Serviceability & Skid Resistance

Where the whole empirical tradition comes from. Students fit the PSI equation themselves to Problem 9.2's five sections and get a rut coefficient of −38.09 against AASHO's −1.38 — 27× larger — with an R² above 0.98. Both facts are true at once, and sitting with that is the most honest introduction to regression a pavement course can offer. Also computes skid number against speed, which is two independent properties (microtexture and macrotexture) wearing one number. Validated against Eqs. 9.14, 9.15 and Problems 9.2 and 9.4.

Built · /tools/reliability/

Reliability & Variability Explorer

Every design input takes a coefficient of variation; the variances propagate through the AASHTO flexible equation to a reliability. Ranks each input's share of the total variance — the chart that decides where money should go. Runs the same question three ways: Taylor's expansion, Rosenblueth's point estimates, and seeded Monte Carlo. Validated against Huang Examples 10.11, 10.12 and 10.13, including the 92.2% reliability the book computes.

Nothing was computing the wrong thing.

The generator's tests are the part worth stealing. They do not check that it emits numbers; they check that the data is solvable. Every generated triaxial set is regressed back to the k-values that made it, every CBR curve is reduced back to its own CBR, and every FWD basin is backcalculated back to the moduli it came from. A generator that produced plausible-looking but unsolvable data would be worse than no generator at all, and that failure is invisible until forty students are stuck on it at once.

A second class of test pins the distribution rather than the validity, because some assignments quietly depend on one. Roughly half the class must get a filter gradation that fails at least one criterion, or HW6's "where they fail, propose a fix" is an empty instruction. Both fatigue and erosion must govern for somebody, or HW9's "report which governs" has a single class-wide answer available from a neighbor. Every slab must land between σ/MR of 0.2 and 1.35, so no student gets a thickness question that is already answered. These are easy to break by adjusting a range and never notice.

A bug worth putting in a lecture. The master curve tool's sigmoid fitter used a hand-written 4×4 solver containing the expression row[i][i]. In JavaScript row is an array of numbers, so row[i] is a number and row[i][i] is undefined — every solution came back NaN. The optimizer dutifully rejected every step and returned its own starting guess.

Nothing looked wrong. The curves were smooth, the R² was 0.78, the numbers were the right order of magnitude, and I drew a confident conclusion from them — that the Asphalt Institute model violates time–temperature superposition. It does not. With the solver fixed the collapse is R² = 0.997, and the real finding is smaller and more useful: superposition holds, but the handbook's average shift slope is wrong for this mix by enough to matter.

What caught it was fitting data whose answer was already known. Not inspection, not plausibility, not the chart looking right — a synthetic sigmoid with parameters written down in advance, and an assertion that they came back. That is the calibration ritual of §07, applied to a tool instead of by a student, and it is the single most transferable habit in this entire proposal.

What is left

The roadmap is empty: every tool this proposal asked for has been built and pinned to the book. Three things remain open, and none of them is a tool.

  • Three tools still carry untested physics — damage, LCA, and the Mr fitter. This is a stopping point rather than an omission. The first two implement assignment and inventory formulas rather than book equations, so there is no printed answer to pin them to; closing them properly needs a worked example written by the instructor, not by me. The Mr fitter is a log-space regression that the dataset generator's tests already exercise indirectly, by regressing generated data back to the k-values that produced it.
  • The generator needs a semester salt and a roster before first use. The CLI refuses to run without the salt for the reason given above; it is the whole security model.
  • None of this is committed or deployed. The homework data files (homeworks.ts, hwGuides.ts) are deliberately untouched — this document is a recommendation, and rewriting the live syllabus is your call, not mine.
10

Getting there from here

This is a large change and it does not have to be made at once. The order below front-loads the highest ratio of pedagogical gain to instructor effort.

  1. Build the dataset generator. Done — scripts/generate-datasets.mjs. Set a semester salt, point it at a roster CSV, and every homework below becomes per-student for free. Start by generating one bundle for yourself and working HW2 from it.
  2. Add prediction-first prompts (D2) to all ten existing homeworks. One sentence per part. No new content, no new grading infrastructure, and it changes what students do with the assignment immediately. If only one item on this list happens, make it this one.
  3. Introduce the AI use log and the verification line. Also nearly free, and it establishes the course's stance before the first homework is due.
  4. Redesign HW1 and HW10 first. They bracket the semester and carry the sealed-prediction thread. HW1 needs no new tooling at all; HW10 uses the two new tools.
  5. Then HW7 and HW3 — the two with the largest gap between current exposure and available tooling.
  6. Then the rest, at roughly one per semester if that is the sustainable pace. The audit table in §01 is the priority order.

What this costs, honestly

  • Student workload has to stay flat, and that requires cutting. This is the risk that sinks redesigns like this one. The parts above are richer than the problems they replace, and richer reads as longer unless something is removed deliberately. Three things make the trade roughly even: fewer parts (HW9 goes from five textbook problems to four graded parts, HW5 from five to five but with three of them tool-driven), no chart-reading busywork where a tool now does it, and a page limit on prose — one page per homework, enforced. If a homework is running past six hours for a competent student, cut a part rather than letting it run. The exemplar in §05 is calibrated at about ninety minutes; use it as the unit of measure.
  • Grading load goes up. A defended choice takes longer to grade than a number. Mitigations: rubric bands rather than point-by-point marking, the micro-defense (D9) as a substitute for written justification on one part per homework, and peer review on the parts where students benefit from seeing another approach. Realistically, budget 30–40% more TA time per homework, offset by the fact that per-student data makes plagiarism detection nearly free.
  • Some students will resent the ambiguity. Assignments without a single right answer are uncomfortable for students trained on assignments that have one. This is worth naming in week one rather than discovering in week six. Publishing an exemplar — one part, fully worked, showing what a defended choice looks like — resolves most of it.
  • Tool trust replaces textbook trust. The failure mode of this redesign is a student who believes the LEA solver the way they used to believe the answer key. The countermeasure is already in the design: HW3 P1 requires a hand solution, HW4 P1 requires two independent solvers to be reconciled, and HW10 P5 requires reporting which numbers the data did not determine. Keep those parts even when the schedule is tight.
  • Equity of access. The AI policy assumes every student can reach a capable model. Free tiers are adequate for everything the red-team parts require, and no part of any homework should require a paid subscription. Worth checking each year.

One closing argument. The reason to do this is not that students might cheat. It is that the skill the profession now needs — reading a model's output and knowing whether to believe it — is the same skill this course has always been trying to teach about design methods. Huang says it plainly about backcalculation, about sensitivity studies, and about the three ways of estimating effective structural capacity: there is no substitute for judgment. That was true before any of this. What has changed is that a student can now generate a confident, articulate, wrong answer in four seconds, which makes judgment the only thing left worth grading.
